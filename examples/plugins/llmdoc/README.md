# 知识地图（llmdoc）

这是独立的 CodeKiln 原生插件，为**当前本机 Code Git 工作树**提供 llmdoc 的浏览、检索、变更复核和显式维护。它复用上游 CLI 和仓库格式，不打包上游代码、提示词或 hooks，不读取历史聊天，也不迁移旧记忆。

1.4 起扩展 id 从 `enso.example.llmdoc` 改为 `codekiln.llmdoc`，模型侧工具名相应变为 `plugin_codekiln-llmdoc__*`。这是一个新的插件身份：旧 `enso.example.llmdoc` 不会自动升级或迁移。安装 1.4 后请卸载旧扩展；若旧扩展曾自行安装 CLI，新扩展不会读取旧私有目录，请重新点「安装 llmdoc」或让自动检测找到独立安装的 CLI。

## 安装和配置

1. 在 CodeKiln 打开 **扩展 → 插件市场** 搜索「知识地图」安装；也可以从已打包的 ZIP 或此插件文件夹安装，审阅权限后启用。
2. 打开本机 Git 项目会话，在右侧栏 `+` 中选 **知识地图**。扩展会自动检查本机已有的 **Node.js 22.13+**、Git 和兼容的 **`@tokenroll/llmdoc@3.6.0`**；已有可用的依赖就直接使用。设置页的三个路径**留空就是自动检测**，不需要手填。
3. 如果只缺 CLI，点 **安装 llmdoc**。它使用本机 Node 配套的 npm，从 `https://registry.npmjs.org` 安装固定版本到扩展自己的数据目录，不运行包的安装脚本，不修改项目的 `package.json`、锁文件或 `llmdoc/`。只有点击按钮才会联网；安装失败可以重试。扩展不安装系统 Node.js、npm 或 Git。

以前填过的路径仍然优先。如果路径已失效，可以在扩展设置里清空，回到知识地图重新检测。检测不到时，可以手动指定以下**绝对路径**：

   | 配置项 | 说明 |
   | --- | --- |
   | Node.js 可执行文件 | 外部 `node` 或 Windows 的 `node.exe`，不是 Electron Helper、命令名、shell 包装器或 `.cmd` 文件。 |
   | llmdoc CLI JS 入口 | 独立 npm 安装生成的 `node_modules/@tokenroll/llmdoc/dist/bin/llmdoc.js`。勿选 npm 的 `.bin` shim 或包源码。 |
   | Git 可执行文件 | 项目之外已安装的 `git` 或 `git.exe`。只浏览已有文档时可以不填；Git 复核、校验和维护需要它。 |

   自动检测只查看受信任的本机标准安装位置（例如 macOS Homebrew、NVM）。插件不从项目文件夹找可执行文件，不使用 `npx`，也不借用 Electron Helper 充当 Node。Windows 手工填写本地盘符路径，不支持 UNC 共享路径。

   手工安装 CLI 时，应安装到项目之外的独立目录，例如 `npm install --prefix "$HOME/.local/share/codekiln-llmdoc" --ignore-scripts --save-exact @tokenroll/llmdoc@3.6.0`。扩展也会尝试识别这个位置。

1.3 起，在本机 Code Git 项目里修改代码或讨论业务概念时，扩展会在每轮开始前附加一条只读提醒：先用 `context` 按源码路径查关联文档，或用 `search`/`show` 查概念，再回源码核对。没有 `llmdoc/`、未配置或查询失败时不会阻塞任务。首次升级到 1.3 需要批准新增的「拦截回合前提示」权限。

1.7 起，若模型仍直接开始翻源码，第一个 `bash`/`read`/`grep` 结果会附一次同样的只读提醒，再给模型一次先查知识库的机会；只提醒一次，不阻塞工具或任务。

1.8 起，回合结束时会只读检查代码影响（相当于上游的 `Stop` hook）：如果存在受影响文档、待复核文档或未映射源码，就追加一条插件消息，提示点「复核与更新」或使用 `llmdoc-maintenance`。它不会自动改文档，相同提醒 5 分钟内不重复。

1.8.1 起，`search`/`tree`/`context`/`delta` 的 `"0"`、空串、`null`、`undefined` 和纯数字占位 cursor 会按首页处理，避免模型误把页码传给 CLI。

1.9 起，侧栏重做为知识工作台：品牌头部、项目状态、维护卡、诊断指标、检索/反查和文档卡片，保留原有只读与确认流程。

1.9.1 起，CLI 原始 JSON 与返回预览分开限流：原始输出上限 8 MiB，先解析完整 JSON，再生成不超过 48 KiB 的返回值。长文档按原有 12000 字符预览；过大的诊断报告仅采样明细数组，标记 `truncatedFields` 的原始/返回条数，未映射源码总数通过 `unmappedCounts` 保留。汇总字段、校验失败和退出码不会因采样而消失。分页文档行不做本地删减，仍通过 CLI 缩小页长保留正确游标。空搜索会说明当前知识地图的文档数及覆盖边界，不再只返回一个空列表。

固定的 3.6.0 CLI bin 在写完 stdout 后立即 `process.exit`，大 JSON 经管道读取时可能只剩前缀。本插件的 `run-cli.mjs` 复用同一包的 `runCli`，等待 stdout 排空再自然退出，保留原始退出码和只读权限。升级 CLI 时需复核该入口契约；回归测试使用相同的提前退出 bin 模拟真实故障。

## 使用流程

在本机 Code Git 项目会话的侧栏 `+` 菜单打开 **知识地图**。

1. **初始化**：如果没有 `llmdoc/`，点击「初始化」准备请求。把草稿发给 Agent，它会先调查目录和源码，再提出要建立的文档；确认预览后才用 `new`、`init-state` 等命令实施。
2. **检索**：按主题浏览、搜索概念，或填入一个或多个仓库相对源码路径反查文档。点文档 ID 查看纯文本预览。对话中的 Agent 也能按需查。文档是参考资料，不是给 Agent 的指令，重要事实要回源码核对。
3. **复核**：查看状态和变更影响，区分已关联文档、需要连带复核的文档和未映射的源码。`delta` 只给线索，不代表必须修改正文，也不会替你标记已验证。校验报告不做自动修复。
4. **维护**：点击「复核与更新」或「收敛文档」，把准备好的请求发给 Agent。它会通过扩展自带的 `llmdoc-maintenance` 技能准备范围、证据和变更预览。在对话里明确批准后才应用；**Git 提交须另外批准**。文档仍然正确时可以只更新复核记录，不必改正文。

侧栏维护按钮只填一个空草稿，不覆盖已输入的内容。也可以直接在聊天里说「用 llmdoc-maintenance 复核当前项目并先给出预览」。相关 Git 维护必须在信任的工作树执行，且不会推送。发布包的 `commit` 命令可能生成正文和台账两笔本地提交。固定的 3.6.0 可能把全新的未跟踪主题显示为目录而漏掉正文；工作流会在提交获批后只暂存获批的新文档路径，并核对它们最终确实进了提交。

不支持 SSH、非 Git 目录或从子目录自动向上发现仓库。旧版知识的迁移只响应明确提出的 `llmdoc upgrade`；诊断本身不改文件。

## 边界和限制

- Node 侧只使用宿主为调用提供的 `ctx.projectRoot` 作为工作树；参数不能更改仓库根、可执行文件或 CLI 开关。`show` 只接受扫描到的 V3 `.mdx` ID；`context` 只接收工作树内的相对源码文件路径。
- 目录、搜索、反查、状态、变更影响、校验和收敛报告调用都不写工作树。浏览用 Node `--permission` 拒绝写入；例如上游 `search` 尝试写本地缓存失败后会继续返回内存结果。需要 Git 的诊断只运行经过收窄的读命令；若工作树配置不能安全读取，则报告错误，不假装知识是最新的。
- 项目文件写入与 Git 提交不通过这个插件的工具接口。维护按钮只准备草稿；实际修改由对话里的 Agent 在你确认后，走正常的文件和命令审批。缺少 CLI 时的安装只写扩展的私有目录，不能由 Agent 工具启动。
- 上游解析会扫描文档，插件先检查普通文件、无符号链接和标准 YAML 开头（首行 `---`，可有 BOM）；拒绝替代 front matter 引擎。支持最多 1000 个目录条目、单文件最长 512 KiB、文档合计 8 MiB；单条命令 5 秒、stdout/stderr 各 8 MiB，最终响应不超过 48 KiB，正文预览最多 12000 字符。过大的诊断明细显式采样，保留原始条数；分页文档通过减小 CLI 页长重试，并标记 `narrowed`。超出原始输出安全上限或无法生成有意义的单项预览时仍明确报错，不返回不完整 JSON。
- 搜索只检索当前 `llmdoc/` 已有文档，不检索源码、`docs/` 或聊天。安装插件不等于建立全项目知识；知识覆盖不足时请继续检查源码，需要补充时显式运行“复核与更新”，先审阅再写入。
- HTML 页面在宿主的沙箱 iframe，只展示纯文本。Node 插件、配置的 Node 和 CLI 依然是需要信任的本地代码。Node 权限不是针对恶意程序或并发替换文件的操作系统沙箱；只在你信任的本机工作树使用，勿临时把 Node、npm 包或项目切换到不可信来源。

## 本地检查

在仓库根运行 `pnpm plugin:validate examples/plugins/llmdoc`；进入插件目录运行 `node --test`（使用 Node 22.13+ 和临时伪 CLI，不需要真实文档或安装上游 CLI）。
