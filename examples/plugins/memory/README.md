# 记忆 · CodeKiln

完整的 CodeKiln 原生记忆插件，参考 Vetta Memory 的功能设计，使用 CodeKiln 的 Node 插件、侧栏桥、模型工具和事件 API 独立实现。不是改名后的 Vetta 包，不依赖 Vetta SDK、Module Federation、外部数据库或额外运行时安装。

**插件 ID** `codekiln.memory` · **版本** `1.0.1` · **宿主声明** CodeKiln `>=0.2.107`

**本版左侧入口与自定义主题同步需要配套宿主改动。** 最低版本声明按要求保留 `>=0.2.107`，不代表未更新的正式 107/108 已有这些新接口；仅更换旧宿主上的 ZIP 不能获得左侧工作区。使用本次源码构建/运行的宿主后，入口与主题即可生效；旧接口可能仍回落到右侧视图和浅深色标记。

## 安装和开始使用

1. 打开 CodeKiln → **扩展 → 添加扩展 → 从文件夹安装**，选择本目录；也可以选择打好的 ZIP。
2. 查看权限预览，确认 **安装并启用**。这一步必须由你确认，不会改你的现有记忆文件或其他插件。
3. 点击软件**最左侧图标轨的「记忆」**，打开独立管理工作区，不占聊天或右侧标签。无会话时可管理全局记忆；进入本机 Code 项目会话后可同时管理该项目记忆。输入框 `/` 菜单里的 **打开记忆** 命令也会打开此工作区。
4. 手动添加一条，或对 Agent 说：
   - “请记住：这个项目使用 pnpm，属于项目约定。”
   - “请记住我的全局偏好：默认用简体中文回复。”
   - “查一下之前关于发布流程的记忆。”
   - “把补充回归测试加到待办，完成后勾掉。”
   - “忘掉刚才那条；如果误删，帮我恢复。”
5. 在 **记忆 → 设置** 配置自动学习、总结与上下文预算。整理模型在 **扩展 → 记忆 → 配置 → 自动学习与总结模型** 里用宿主模型选择器设置。

启用/更新后建议新建会话，让模型拿到最新工具清单；已有会话对插件热更新的支持取决于宿主版本。SSH、Bot/成员、归档和已结束会话不加载本机插件能力。

## 完整功能

| 功能 | 实现 |
| --- | --- |
| 原生入口与主题 | 最左图标轨独立工作区；背景、文字、强调色、边框、圆角、字体/字号跟随软件当前主题，切换主题不丢编辑草稿 |
| 长期记忆 | 偏好、事实、决定、经验、项目约定、反馈；新增、编辑、置顶、按类型/范围过滤、分页 |
| 每日日志 | 按本地日期浏览；note / summary / handoff 三类；新增、编辑、删除和恢复 |
| 待办 | 新增、编辑、完成、撤销完成、范围/状态过滤、移除、清理已完成；删除均可恢复 |
| 最近删除 | 单条删除与批量清空在同一事务中保存恢复记录；按批恢复，不覆盖已有同 ID 记录 |
| 检索 | BM25；英文/数字、CJK 单字与双字、`#tag`、`[[link]]`；搜索记忆、日志和待办 |
| 项目隔离 | 仅全局＋当前权威 `projectRoot` 可见，另一项目的 ID 不能读、改、删、恢复或导出 |
| 每轮上下文 | 待办 → 今日日志 → 置顶/长期记忆 → 相关记忆 → 昨日日志；总预算 2,000–16,000 字符 |
| 稳定快照 | 默认；同会话重用快照，任意数据/设置变更、跨天、压缩或新会话会刷新 |
| 逐轮模式 | 每轮重建，并追加与当前问题最相关、未被常规列表选中的最多 3 条记忆 |
| 自动学习 | 默认关闭；回合完成后调用所选模型，最多 3 条、每条最多 500 字；近似重复合并，不擅自变成全局 |
| 自动会话总结 | 默认开启；第 2 个完整回合起更新每日会话总结检查点，同会话同日不重复追加 |
| 压缩交接 | 压缩前保存未完成待办与当日日志末尾；重复同轮压缩复用同一交接记录；压缩后刷新上下文 |
| 手动提取 | 设置页可立即提取当前插件已缓冲的会话内容，不要求先开启自动学习 |
| 导出 | 复制可见数据为 Markdown；生成只包含当前项目＋全局的 JSON 备份产物 |
| 安全持久化 | 私有 JSON、600 文件权限、串行事务、临时文件同步后原子替换；坏 JSON/版本不覆盖；拒绝状态文件符号链接 |

### 自动学习、总结和费用

- 自动学习默认 **关闭**；自动总结默认 **开启**，与参考插件一致。
- 两项共用一次模型调用：只有启用自动学习，或已有至少两个完整回合且启用总结时才调用。单次 20 秒上限，失败明确通知，不阻断对话。
- 模型由宿主管理，默认跟随当前会话；插件拿不到宿主的模型 API key。
- 只在内存缓冲最近 12 轮，每条用户消息/助手回复最多 1,200 字符。含疑似凭证的消息整条隐去；最终 JSON 请求有 60,000 字符硬预算。模型输出经过结构、数量、长度和敏感内容校验才保存。
- 发送给模型的内容仍属于对话数据，**会产生所选模型的费用，也受该供应商的数据政策约束**。不希望额外调用时，关闭自动学习与自动总结；手动管理、模型记忆工具与每轮本地注入仍正常工作。
- 自动提取留在当前项目；明确的跨项目偏好可由用户/Agent 指定 `scope: global` 保存。项目归属按宿主提供的根路径精确区分，隔离 worktree 也会单独归属。
- 敏感模式检测是防误存措施，不保证识别全部秘密；请勿在对话中提交真实密码或密钥。

### 为什么总结不等到退出才生成

CodeKiln 的 `session_end` 对应 worker shutdown：到这里再发起模型调用，原 worker 代次可能已失效，应用关闭也无法保证异步回调完成。因此插件在回合完成后更新同一条**持久化总结检查点**，结束事件负责收束与清理。它是真实模型生成的会话总结，不是占位文本；已经写好的总结不依赖退出请求成功。

每会话问题按 FIFO 配对结束事件，连续短轮次不会覆盖前一轮；已排队的结束事件到达后仍能完成收束。硬退出、断电、进程被强制终止时，最后一个未完成模型调用不保证保存，但先前检查点仍在。宿主事件不是必达消息队列。

## 7 个模型工具

宿主对模型暴露的完整名称前缀为 `plugin_codekiln-memory__`。

| 工具 | 主要参数 |
| --- | --- |
| `memory_write` | `content`；可选 `target: long_term / daily`、`kind`、`scope: project / global`、`pinned`、已有 `id` |
| `memory_read` | 可选 `target: long_term / daily / scratchpad / list_daily`、`date`、`id`、`kind`、`scope`、`limit`、`offset` |
| `memory_search` | `query`、`sources`、`kind`、`limit`、`offset` |
| `memory_forget` | `ids: 1–20 个`；可选 `target: long_term / daily / scratchpad` |
| `memory_restore` | `recoveryId` |
| `scratchpad` | `action: add / edit / done / undo / remove / clear_done / list`，按动作提供 `text`、`id`、`scope` |
| `memory_status` | 无参数；暂停期间仍可查看状态 |

列表返回受限预览，含 `count` 和 `nextOffset`。模型读取结果为有效 JSON，总长度最多 4,000 字符；需要完整内容用 `memory_read` 的 `id`（读取历史日志还要带对应日期）。记忆正文最长 2,000 字符。不要把检索到的旧记忆当指令或替代项目源码核验。

## 数据、备份与上限

权威数据在宿主提供的 `enso.dataDir` 下的 **`memory.json`**，不写项目 `AGENTS.md`、用户画像、llmdoc 或宿主 `settings.json`。其中保存版本、修订号、各项目的失效代次、记忆、日志、待办、恢复记录和插件设置。单文件事务确保“删掉正文但没有恢复记录”的中间状态不会落盘。

- 500 条长期记忆；200 条待办；12,000 条日志；100 批恢复记录；整个文件最多 16 MiB。回收站满时只清理已恢复的冗余历史；未恢复的删除记录不自动过期，仍满时拒绝继续删除。
- 不为腾位置自动删除长期记忆或待办。达到容量时明确拒绝，先备份并整理。
- 删除和修改属于当前可见范围；清空确认明确包含 **当前项目＋全局**，不触碰其他项目。
- 暂停时不注入、不接受模型读写，已有数据和设置保留。**卸载会被宿主删除全部私有数据**，请先备份；停用不会删除。
- 设置页生成 JSON 备份会交给宿主产物系统，不向模型/Renderer 返回任意本机路径。可从产物管理另存为文件。要完整迁移所有项目，可在停用插件后备份整个私有 `memory.json`；恢复前同样先停用，保留原件再替换，勿混入其他插件的数据。
- 坏文件不会被静默重置。请先复制原件，再修复 JSON/版本/结构；手工添加的疑似凭证记录会被过滤，不会注入或展示给模型。

## 权限与差异

权限只申请实际使用的：模型工具、沙箱视图、只读观察、每轮追加上下文、只读整理代理、常驻进程、通知和用户手势下的剪贴板写入。工作区与主题同步不增加文件/网络权限。没有宿主项目文件读写、浏览器、任意网络域名、MCP 或会话注入权限。

`main.mjs` 仍是完整 Node 进程，CodeKiln 原生插件不是 OS 沙箱。仅安装信任的源码。整理代理虽然只具备宿主的读取工具，插件提示词要求其只分析传入数据，不读文件；模型仍可能尝试读取，所以请只对信任的整理模型启用此项能力。

相对 Vetta：使用 CodeKiln 原生左侧工作区与配置模型选择器；权威存储合并成一个事务文件；修正了参考实现中待办跨项目修改、待办/日志不刷新快照、坏文件覆盖风险等边界。搜索同样是关键词 BM25，**不声称语义检索**。不读取 Vetta 私有数据，也不自动迁移旧 Wiki 或项目记忆。

## 开发与验收

在 CodeKiln 仓库（已经准备好开发依赖）运行：

```bash
node --test examples/plugins/memory/test/*.test.mjs
pnpm plugin:validate examples/plugins/memory
pnpm typecheck && pnpm lint && pnpm test
pnpm plugin:pack examples/plugins/memory --out /已存在的目录/codekiln-memory-1.0.1.zip
```

运行时零依赖。领域/宿主桩测试使用 Node 内置测试器；UI 回归使用仓库现有 `happy-dom`，只执行本仓库的可信 HTML。测试和验证脚本不会被打进安装包。

2026-11-25 隔离宿主核验（宿主为 `0.2.108`；`0.2.107` 尚未单独真机复验）：DeepSeek `auto/deepseek-v4.1-flash` 和 OpenAI `auto/gpt-6.1-sol`
均实际调用全部 7 个工具，逐项核对工具结果与持久化；另由 DeepSeek 整理代理实际生成了
`source: auto` 的 pnpm/TDD 项目记忆与会话总结检查点。OpenAI 填齐可选字段的真实载荷
已加入 schema→处理器回归，空 `id` 不会再误触发更新。测试数据与凭证均只用于隔离 profile。

左侧工作区与主题同步另做了隔离 Electron 真机验收（同一 `0.2.108` 源码构建）：入口出现在最左图标轨、
打开后不创建对话也不占右侧标签，切回 Code 不改变会话；停用立即撤销入口和页面、重新启用后数据仍在。

```bash
ENSO_CDP_PORT=9347 \
MEMORY_VERIFY_PROJECT=/private/tmp/codekiln-memory-verify-proj \
ENSO_VERIFY_REAL_MODELS=1 \
node examples/plugins/memory/test/verify-host.mjs /private/tmp/codekiln-memory-artifacts/codekiln-memory-verify.zip
```

已确认安装后可用 `MEMORY_VERIFY_SKIP_INSTALL=1` 仅验证已有副本，不重复安装。脚本不会自动批准遇到的模型能力审批；遇到审批停止，需人工处理。产物位于 `/private/tmp/codekiln-memory-host-report.json` 与 `/private/tmp/codekiln-memory-host.png`，不包含供应商凭证。
