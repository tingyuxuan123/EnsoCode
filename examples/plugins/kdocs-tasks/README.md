# 金山文档需求助手：阶段 0 接入准备

**当前仅有接入指南，不是可安装插件。** 官方授权及测试副本的读写门禁尚未通过；本目录没有 `enso-plugin.json`，不要安装、启用或视为已交付。

目标闭环：读取负责人为“谢”的需求 → 人工确认领取 → 关联 Collabra 项目会话 → Agent 处理 → 人工确认回填备注、测试情况和复测步骤 → 待测试。负责人不变，最终验收不自动完成。

## 1. 先确认能否申请开放平台

[官方入驻指南](https://developer.kdocs.cn/isp/access/access-open-kdocs.html)目前面向企业服务商，要求企业信息、官网、联系人和营业执照，并进行审核，不能承诺个人账号直接开通。

1. 使用有权访问需求表的金山文档账号登录[开发者后台](https://developer.kdocs.cn/admin/servicer)。
2. 已有企业服务商的，联系管理员取得应用开发权限；尚未入驻的，按官方要求提交真实企业资料。
3. 没有相应企业资质时，先咨询开放平台是否接受此内部工具场景；不要提交不实资料，不要以 Cookie、未公开接口或其他人的凭证绕过申请。
4. 审核通过后，在[应用申请入口](https://developer.kdocs.cn/admin/apply)申请用于内部验证的应用，以后台当前可选类型为准。说明用途：读取本人负责的需求，经人工确认更新限定状态、备注和测试记录，不做无人值守最终验收。

不能申请成功时，阶段 0 保持阻塞，由用户另行决定接入方式，不自动切换浏览器方案。

## 2. 准备隔离的测试表与读写权限

- 由文档所有者允许后，手动准备与真实需求表类型、列结构一致的**脱敏测试副本**，不上传客户资料、生产账号或敏感业务数据。
- 使用有编辑权限的账号授权。能在浏览器打开分享链接，不等于第三方应用也有官方 API 权限。
- 保留实际列名，准备几条虚构需求：唯一编号、负责人“谢”、其他负责人、不同状态。用唯一编号识别任务，不以行号为身份。
- 指定一处可试写的空白单元格/区域，确认不包含公式、合并、保护或生产数据。后续任何实际试写都只限此范围；不能根据“批准开发”推定整表写权限。
- 记录团队已有的“可领取 / 处理中 / 待测试 / 受阻”状态名称，以及允许更新的列。缺少唯一编号时先由用户协调；插件不会擅自加列。

先验证文件类型，再决定 API：

| 类型/接口族 | 官方当前列出的能力 | 阶段 0 处理 |
| --- | --- | --- |
| `et` WPS 表格 | 工作表信息、单元格读取，未列出单元格写入 | 不假设可以回写，需官方确认支持路径 |
| `ksheet` 在线表格中的普通工作表 | 工作表信息、单元格读取和更新 | 在测试副本验证文本、范围和读回行为 |
| 数据表、轻维表 | 记录/字段接口，身份与普通单元格不同 | 不冒充普通工作表；先确认是否需要调整适配范围 |

**注意：** `ksheet` 的 `sheets_info[].sheet_type` 可以是 `et`（普通工作表）或 `db`（数据表）；这不等于整个文件属于 `/et/` API。不要仅凭文件名、截图或该字段决定接口族。工作表的稳定 `sheet_id` 与随排序变化的 `sheet_idx` 也不能混用。

## 3. 申请授权范围

按[更新单元格接口](https://developer.kdocs.cn/server/ksheet/workbook-update-cells.html)目前的权限表，申请并经用户同意以下范围：

| scope | 用途 |
| --- | --- |
| `user_basic` | 接口文档要求的用户基本信息权限 |
| `access_personal_files` | 访问文档列表及读取工作表 |
| `edit_personal_files` | 更新文档内容 |
| `download_personal_files` | 更新接口目前列出的依赖权限；首版不因此自动下载附件 |

不申请删除、移动、创建文档或通讯录权限。后台与当前文档要求不一致时，先核对官方说明，不默认扩大范围。

## 4. 在自有服务端取得短期令牌

遵循[官方 Web 授权](https://developer.kdocs.cn/common/authorization/web.html)：

1. 在应用后台登记你控制的回调地址，准备处理回调的服务端；需要能校验随机 `state`，不能把未经校验的回调当成有效授权。
2. 从服务端生成并打开授权链接，参数包括 `app_id`、上述逗号分隔的 scope、编码后的 `redirect_uri` 和随机 `state`。
3. 使用目标账号同意授权，服务端验证返回的 `state`，取得 `code`。官方说明 code 有效期为 5 分钟。
4. **只在服务端**使用 `app_id`、`app_key`、`code` 调用 `/api/v1/oauth2/access_token`；检查 HTTP 结果和业务 `code`，不要打印完整请求或响应。
5. 首版只向本机私有配置转移短期 `access_token`，另记服务端返回的 `expires_in` 和取得时间。官方通常为 24 小时，以实际返回为准。过期后重新授权。

`app_key`、`refresh_token` 始终留在你控制的服务端，不放入插件、仓库、模型提示词或聊天。首版不实现授权服务、自动续期，也不以网页 JavaScript 交换令牌。

官方说明要求令牌存放及通信在服务端完成。轻量版拟由受信任的本机 Node 插件侧调用业务 API，不把令牌交给网页或模型；**是否符合你的应用接入要求仍需与平台确认**。若平台要求自有远程服务代理业务请求，先停止并说明所需范围变化，不擅自把密钥下发桌面端。

不要把令牌作为命令行参数，或粘贴到带历史、代理日志的请求工具中。官方 API 使用查询参数携带令牌，服务端访问日志也必须脱敏。

## 5. 获取官方文档 ID 和工作表信息

授权后，在服务端调用[最近文档列表](https://developer.kdocs.cn/server/personal/files-recent.html)：

```text
GET https://developer.kdocs.cn/api/v1/openapi/personal/files/recent
```

该接口包含收到的分享文档，使用短期令牌并按 `next_offset` 分页；它只是查找入口，不保证这份共享文档一定能被应用读取。核对名称、所有者和测试副本，不能只按同名文件选中目标。

[官方 FAQ](https://developer.kdocs.cn/server/guide/question.html#file_token)说明：文档 `id.open_id` 或 `id.union_id` 均可作 `file_token`。本插件场景优先使用当前应用返回的 `open_id`。**分享链接 `/l/` 后的短码不是这个 ID**，不猜测转换、不使用浏览器内部接口反查。

确认是适用的在线表格后，调用[工作表列表](https://developer.kdocs.cn/server/ksheet/workbook-sheets-info.html)：

```text
GET https://developer.kdocs.cn/api/v1/openapi/ksheet/:file_token/sheets
```

记录 `sheet_id`、`sheet_idx`、`sheet_name`，在测试副本小范围[读取表头和测试行](https://developer.kdocs.cn/server/ksheet/workbook-get-cells.html)。`row_from`、`row_to`、`col_from`、`col_to` 为从零开始的索引，不能直接把界面行列号照搬。

暂不提供写入命令：官方更新接口使用 `op_type: formula`，文本转义、换行、选区终点及公式执行行为必须先在获准测试区域验证。不能因为返回 `code: 0` 就认定是安全的纯文本写入。

## 6. 安全地把准备情况交给开发者

令牌不要发到聊天。在仓库之外、非云同步的本机私有目录准备文件，仅当前用户可读；macOS/Linux 文件权限应为 `0600`，Windows 需设置对应 ACL。不要仅依赖 `.gitignore` 保护凭证。

文件内容示意（占位值，不是有效配置）：

```json
{
  "access_token": "<仅在本机私有文件填写>",
  "obtained_at": "<实际获取时间及时区>",
  "expires_in": 86400
}
```

聊天中只需提供以下**非凭证明细**，不知道的项可以写“待查询”：

```text
应用状态：审核通过 / 审核中 / 无法申请
令牌私有文件的绝对路径：
令牌是否仍有效：
本机 Node 业务调用是否获平台允许：
测试副本文档链接：
官方 file_token（非 access token）：
工作表名称 / sheet_id / 当前 sheet_idx：
允许试写的空白单元格或区域：
表头位置、需求编号列、负责人列、状态列：
可领取 / 处理中 / 待测试 / 受阻的实际状态：
允许更新的列：
```

文档链接和 file_token 虽不是授权令牌，也不要发布到公共 issue、示例或仓库。由用户指定试写范围后才进行网络写入；不扫描其他本机配置寻找令牌。测试结束撤销测试令牌或等待失效，按需清理私有文件。

## 7. 阶段 0 验收清单与当前状态

必须逐项取得证据，不能用文档声明或模拟测试代替：

- [ ] 应用准入和目标账号授权通过；令牌有效，桌面 Node 调用方式获允许。
- [ ] 分享文档及其测试副本确实能通过官方 API 访问；确定文件类型和接口族。
- [ ] 确定稳定文档/工作表标识及唯一需求编号，能读取实际字段和状态。
- [ ] 用户指定试写区域后，单字段写入和读回一致，不影响其他单元格。
- [ ] 普通文本、换行、公式样式前缀、长度和选区范围语义验证通过。
- [ ] 明确版本条件更新支持情况；没有原子条件更新则记录并发窗口，不宣称严格锁定。

当前只核对了官方文档；尚无应用、令牌和获准试写副本，以上各项**均未验收**。因此没有生成插件清单或运行时代码，没有真实文档读写，也未执行插件静态、Electron、模型或业务测试。通过门禁后才继续插件实现，不替用户假定已获授权。
