# 需求助手

## 0.2.3 界面精简

移除输入框旁的重复入口。从右侧面板手动打开需求助手即可，报告结果工具卡保留。

## 0.2.2 修复

“读取待办”现在使用宿主固定的只读表格入口，新对话不用先发消息，计划模式也能读取。读取失败会明确显示失败，不再把未读取或断开的缓存显示成“没有需求”。切换链接或负责人会撤销旧列表与确认；真正领取和回填仍遵守会话写入限制。更新插件后须重启 dev 以加载主进程新能力，不能只刷新侧栏。

粘贴需求表链接，读取我的待办，选一条交给 Agent，最后核对结果回填。

## 怎么用

1. 在当前项目的对话里，从右侧面板手动打开 **需求助手**。
2. 粘贴金山文档链接，负责人默认“谢”，点 **读取待办**。
3. 在想处理的需求上点 **开始处理**，看清改动后点 **确认并交给 Agent**。任务提交到当前对话；会话忙时排队，不重复发送。
4. 处理后打开报告，核对 **处理说明、测试情况、复测步骤**，点 **预览回填 → 确认回填表格**。

不需要填写列号、JSON、DOM选择器、校准格或测试开关。读取不会修改表格；实际更新仍需你确认。

## 适配的表

自动识别“需求、状态、负责人、备注”四个表头。编号和测试列都不是必需的：

- 空状态视为待处理；处理后改为处理中，交付后只改为待测试/受阻。
- 没有编号时用需求内容和负责人识别；内容完全重复会提示，不会随便选一行。
- 没有“测试情况”列，就把处理、测试及复测说明一起追加到“备注”。
- 不改需求正文、负责人、优先级、提出人，不增加或删掉表格列。
- 当前读取所选工作表前200行、前12列。较大表格或不同表头会明确提示，不自动猜测。

## 安装

需要包含本次浏览器选区读取能力的 Collabra。使用 dev 时先重启一次，再在 **扩展 → 从文件夹/ZIP安装** 更新本插件。仅热更新界面不够，旧安装版也可能需要更新宿主。

v0.2.0 新增“向当前对话提交任务”权限，升级时需要重新确认；不会自动安装或替你同意。

## 注意

- 用你在内置浏览器里正常登录的账号；插件不索取密码、Cookie或令牌。
- 表格用画布渲染，插件读取正常复制选区产生的文字，不读取系统剪贴板或网页私有数据接口。
- 同步时不要同时编辑或排序。回填前会重读核对，失败或结果不确定时点“核对表格”，不会自动重试写入。
- 现有备注保留。暂不支持向含多行/公式的原备注自动追加；遇到这类内容会停止，不冒险覆盖。
- 测试通过是填写者/Agent的声明，不是插件独立验收；不会自动设为已完成、已验收或已上线。
