# EnsoCode 全功能 UI 重构范围

## 结论

重构对象是当前 EnsoCode 的全部功能 UI，不是一个主工作台换皮，也不是照搬 Proma 的功能。Proma 当前源码只提供视觉和布局参考。先完成可交互设计，再另行进入真实应用的代码重构。

当前清单按 8 个功能域拆分为 90 个初步设计验收单元。它是设计范围的粒度，不是产品宣传功能数量，也不代表盘点已经穷尽所有条件分支。每批设计前继续读取对应功能源码，发现遗漏同步补充，不删除难做功能。

首批六个场景：对话工作台、新建任务、改动审查、外观设置、当前进度、后台 Agent。随后新增项目管理、运行控制（审批/提问/计划/目标/队列）和全功能清单，共 9 个画布场景。当前 21 个单元已有部分设计；完整验收仍为 0，不能当作整个项目 UI 已完成。

扩展验证：项目必填拦截、目录回填、添加后列表回显；受保护请求不出现会话授权、单次授权、问题选择回显、批准计划后执行态、目标暂停/继续入口、队列编辑均已在浏览器预览验证。全部设计源文件通过独立类型检查。

仍需完善：项目分组颜色/批量选择、项目设置的逐项目状态持久化、完整审批队列与请求超时、Agent 提问提交中/超时、完整队列附件、真实功能上下文中的嵌入布局，以及清单其余待设计项。当前项目管理和运行控制用于集中审阅组件，不表示产品必须新增这两张独立页面。

## 同一套设计语言，不做功能删减

- 参考 Proma 当前 `modern` 外壳和 `ocean-light` 令牌；不采用 README 旧截图的绿色大圆角。
- 低饱和蓝灰、6px 紧凑圆角、平铺分栏、细线、Inter 与系统中文字体。
- 不把 Bot 模式改成普通编程会话的别名，不混淆一次性 Subagent 与长期 Coworker。
- 不把实际功能用“待接入”提示替代，也不把说明卡片计为该功能已设计。
- 共用主题、导航、输入、弹窗、列表、菜单、确认、状态与反馈，避免每个页面自成一套风格。
- 手机伴侣属于已发现的独立界面范围，采用同一设计语言、独立移动布局与文档，不套用桌面外壳。

## 执行批次

| 批次 | 重点 | 交付方式 |
| --- | --- | --- |
| 当前 | 范围与基准 | 建立逐项清单；校准首批六场景，不声称完整覆盖 |
| 核心工作流 | 项目/会话、输入/模型、审批/提问、计划/目标、任务/协作、Worktree | 完整主要路径和弹层，逐批截图与交互验证 |
| 生产工具 | 文件/预览/内容搜索、Git、终端、浏览器、旁路、工作流运行 | 以真实工具栏/操作/状态设计，不止静态输出 |
| 设置能力 | 全部设置类别及向导/编辑器/导入、记忆、工作流设计器 | 列表→编辑/配置→确认/失败的完整流程 |
| Bot 与团队 | 成员、群聊、收件箱、看板、委派、例程、记忆 | 多成员状态和任务闭环，含权限/预算/阻塞 |
| 跨设备与系统 | 节点/手机、首启/OAuth/更新/退出 | 桌面/移动分开验收，覆盖连接和权限边界 |
| 总体验收 | 清单对账、视觉与交互、深浅主题、状态覆盖 | 逐项标记完成；未完成项保留，不将其隐去 |

以上为分批推进顺序，不是后台定时任务，也不意味着在会话结束后会自动继续工作。

## 完成标准

每项至少明确：
1. 当前入口及真实功能边界；
2. 主要路径和高频操作；
3. 创建/编辑/保存/取消/确认及未保存更改；
4. 适用的空、加载、失败/重试、禁用/权限、处理中、成功；
5. 桌面/手机只读或安全边界；
6. 可点击的预览行为及正确的跨页面跳转；
7. 截图无异常换行、遮挡、空图标、未定义令牌；
8. 与功能清单对应，给出可定位的场景或组件。

不要求不存在的状态，也不添加源码中没有的业务功能。每批开始前读取该模块实际控件，清单不能代替源码。
