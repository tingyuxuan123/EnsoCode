# EnsoCode UI 重构设计契约

## 范围与边界

- 最终范围是当前 EnsoCode 的全部功能 UI：Code 工作台、右侧停靠面板、设置（21 类）、Bot 模式、远程节点、手机伴侣、首次引导与系统状态。先交付独立可交互设计，不修改应用代码、IPC、store、worker 或真实用户配置。
- 一次交付不等于真机验收：每项仍需在真实应用里逐条核对行为与状态。
- 全量范围以 `components/coverage.ts` 为可搜索目录，逐项给出源码入口、核心动作、弹窗和状态；`frames/coverage.tsx` 显示实际覆盖情况。
- 示例会话、代码、文件改动、运行结果和费用均为设计演示，不代表真实仓库执行或检查结果。
- 相邻问题不处理：真实 Agent 调用、终端执行、模型接入、配置持久化、后端实现、发布。

## 结构：一张画布，多种外壳

真实应用不是「一个大页面 + 侧栏」，而是按路由换外壳。设计稿沿用同一套外壳划分（`frames/_layout.tsx`）：

| 路由 | 外壳 | 说明 |
| --- | --- | --- |
| `/`、面板与运行条各帧 | Code 主窗口 | 56px 图标轨 + 264 侧栏 + 对话 + 360 右侧停靠面板 + 24px 状态栏 |
| `/settings-*` | 独立设置窗口 960×680 | 240 分类导航 + 内容区；子流程用 `/settings-<分类>--<子流程>` |
| `/bot*` | Bot 模式 | 标题栏居中 Code\|Bot 分段 + 图标轨 + Bot 侧栏 + 会话 + 可选资料面板 |
| `/remote*` | 远程节点 | 整块换成对方的目录与会话 |
| `/phone*` | 手机伴侣 390×844 | 独立移动布局，不套桌面外壳 |
| 弹窗类帧 | Code 主窗口 + 浮层 | 项目、分组、搜索、退出、OAuth 等都不占用页面 |

## 固定视觉规则

- 沿用用户认可的 Proma `ocean-light` 蓝灰：背景 `hsl(205 35% 94%)`，内容 `hsl(205 30% 97%)`，文本 `hsl(210 30% 15%)`，强调 `hsl(205 50% 50%)`；令牌见 `theme.css`。
- Inter + 系统中文字体；等宽只用于代码、路径、cron 与 JSON。
- 6px 圆角；工作区无卡片外框、无渐变；分栏只用 1px 细线；阴影只给浮层（菜单、弹出面板、toast、对话框）。
- 字号：正文 13–15px，元信息不低于 11px。
- 1440×900 桌面：图标轨 56 + 侧栏 264 + 主区 + 右侧面板 360（默认，最小 280，对话区至少 360）。

## 数据与交互

- 共享导航、项目会话、改动统计、模型与审批、主题状态集中在 `components/{data,Workbench}.tsx`，单一来源。
- 共用外壳在布局路由；跨页用 react-router `Link`；弹窗由 `useWorkbench().projectDialog` 等状态驱动。
- 面板视图的状态由帧注入（`PanelFrame` + `pushPanelPreset`），每张图能落在不同分支状态上。
- 所有交互只在设计预览内生效，不写真实配置、不发网络请求。

## 验收

一个功能只有在主要路径、编辑/确认、空/加载/失败/权限状态、跨页面交互和最新截图检查都通过后才算完成；「只存在入口」「弹出说明」「只展示正常态」都只能记为部分覆盖。
