# 本地群任务托管

这是 Super-agent 方向的第一步，不是完整的云端常驻 Agent。沿用 Bot 的
`GroupTask → Delegation → 成员任务会话`，不另建任务系统，也不合并 Code 会话的 todo。

## 行为差距与层归属

普通群路由决定谁接话；托管在它之前识别**明确指向既有任务的补充**，直接交回原执行。
后台看护属于 Main，不能依赖当前是否打开聊天页。Renderer 只展示配置、时间线和已有任务卡。

关键文件：

- `src/main/services/bots/taskSupervisor.ts`：根群授权、编号直通、异常提醒及去重。
- `groupChat.ts`：人类消息落盘后、普通选人之前调用托管；机器人消息不走真人补充入口。
- `groupTasks.ts`、`delegationService.ts`：复用原任务回复、原成员会话、审批和投递回执。
- `src/main/ipc/bots.ts`：生命周期接线、根群开关更新与事件去抖。
- `src/shared/types/bot.ts`、`botIpc.ts`、`botsInput.ts`：持久化和 IPC 输入契约。
- `GroupInfoPanel.tsx`：群信息中的中英「任务托管（本地）」开关。

明确不做：自然语言自动猜测任务归属、抢待办、跨群派单、外部 webhook、云端/daemon、
退出应用或电脑休眠后的持续执行，以及模型判断任务方向是否偏离的语义 Watchdog。

## 开启与使用

在 Bot 群聊右侧「群信息」开启「任务托管（本地）」。旧群、新群均默认关闭，
开启本身不触发模型请求或执行任何待办。成员先通过既有指派/委派建立任务执行。

在同根群任意话题中发送纯文本，例如：

```text
#3 仅修改 Safari，不改其他浏览器
任务 #3：使用刚才提供的测试账号
task #3: Safari only
```

- 首部只能有一个明确编号，必须有补充正文，正文不超过既有任务文本上限。
- `doing` 的 queued/running 委派：作为人类补充进入原执行。
- `blocked/need`：复用原任务回复入口，在原成员任务会话中创建一次新的 reply 执行。
- todo、review、done、canceled、执行失败、成员失效或编号不存在：只提示查看任务卡，
  不退回普通选人让模型意外启动/复活任务。
- 裸编号、只在正文中提到编号、多个独立任务号、显式 @、附件、聊天/技能/任务引用仍走原群路由，
  不猜测归属、不悄悄丢掉附件或引用。显式 @ 和普通聊天不属于托管自动行为。
- 首部任务号之后的色值（例如 `#2563eb`）和显式 `issue #12`、`PR #12` 引用保留在正文，
  不作为第二个任务号；无前缀的独立纯数字 `#N` 按潜在任务号处理。

## 身份、确认与结果

- 任务编号只在根群内解析；执行记录必须同时匹配任务、当前委派、负责人和根群。
- 开关只读根群权威记录；话题的复制字段不能成为授权源。团队导出、克隆和新建输入不传递授权。
- 直通消息使用 `task-followup:` + SHA-256(`[chatId, entryId]`) 作稳定投递身份，
  避免跨话题串号，且不超过 worker 的 128 字符边界。
- 执行中补充先进入既有 `Delegation.appends` 账本，再交宿主投递；消费回执与轮次结束
  决定是否完成。入队不代表已被模型处理。
- 同一人类 deliveryId 重发不重复写时间线或创建执行。已落盘消息的直通失败写明确提示，
  返回聊天接受成功不等于执行成功，避免客户端误以为原消息没发出而自动重发。
- 补充被推迟到下一回合时，保留主回合与补充回合的报告；只向委派者结算一次。

## 看护与受控恢复

Main 使用既有宿主 `silences()`、任务和委派权威状态巡检，每 30 秒兜底；相关事件在最后一次变更
后等待 750 毫秒再合并巡检。巡检直接读取启用群的任务快照，只按当前任务的委派 ID 查询，
不为旧任务补执行历史；编号直通也只查指定任务与委派。审批/提问等等待状态沿用宿主豁免；
这里检测的是无输出，不是语义上的无进展。

中断/失败、缺信息和静默分别给出处理提醒；不自动停止、重试、改派或批准工具。
托管失败不单独唤醒委派者。混合批次的回流仍保留每项的身份和终态：失败项仅注入
「等待人工恢复，不要重试或重新委派」，不把具体失败内容注入父模型；整批都等人工时不唤醒父模型。
人应先核对最后的工具结果，再使用已有任务卡操作重试、改派或取消。

提醒以稳定时间线 id 持久化，查找覆盖新对话分隔线之前的历史，重启不重复刷通知。
提醒 I/O 异常不得打断任务主链路。关闭 Bot 模式会销毁计时器和待巡检回调；
关闭群托管只停止该群直通与提醒，不取消既有明确授权的执行。

会话恢复不等于命令可以重放。进程重启后沿用现有 interrupted/blocked 语义，
未完成补充明确标失败，等待人工确认；不承诺恢复内存队列或提供 exactly-once 外部副作用。

## 回归与真机验证

核心回归在 `taskSupervisor.test.ts`、`groupChat.test.ts`、`groupTasks.test.ts`、
`delegationService.test.ts`、`groupDelegation.test.ts`、`bots.test.ts`，另有共享解析、
根群/话题持久化和 `GroupInfoPanel.test.tsx`。

模型验收使用隔离 userData 与独立 CDP 端口：至少两个不同厂商，观察真实 `delegate`、
`report_blocked`、人类编号答复、同会话续做、交付与重复发送；核验 Main 权威历史，
不能仅凭发送接口返回 ok 宣称完成。检查后清理隔离配置和测试进程，不改真实用户群。
