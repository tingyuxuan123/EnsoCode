# 可复现审查（interrogate）

内置工作流 `interrogate` 借鉴「能复现才报告」，不复制上游的工作树创建或命令执行。
它只使用现有只读 `reviewer` 类型，不接受带 MCP 或可写的同名类型；不安装依赖、
不执行候选中的命令、不改项目，也不提供操作系统隔离。

1. 运行 `workflow`，传 `preset: "interrogate"` 和 `args.target`（文件或变更范围）。
   两个 reviewer 并行给出具体检查；`needs-evidence` 的 `checks` 是待验证项，**不是问题报告**。
2. 用户或主代理按现有授权执行选定的复现步骤，保存相关输出。不要盲跑候选里提供的命令；
   缺权限、无复现环境或只有推测时，应说明未验证。
3. 再运行同一预设，在 `args.checks` 传原检查数组的 JSON 字符串，`args.evidence` 传实际输出
   （最多 8,000 字符，保留足以识别检查项和失败行为的上下文）。只有输出没有原检查项会被拒绝。
   第三位 reviewer 独立对照输入、预期与实际表现。只有引用能在所给输出中逐字找到的候选
   才进入 `findings`；没有证据不会生成已验证问题。无需在第二轮重新发现候选。

该预设验证的是**所提供的输出是否支持结论**，不能证明输出来自真实命令。
只回填可信的复跑结果，先去除凭证、私密路径和无关内容。没有发现不代表代码无缺陷。
若设置要求 reviewer 自选模型，沿用工作流原有的顶层 `model` 参数。
