# Web 同一配对多页面互踢重连

## 症状

Web 设备状态在「连接中 / 已连接」之间反复切换，页面看起来一直闪。服务端健康检查正常，
中继没有重启，配对凭据也未失效。多个标签页、独立 PWA 或另一个浏览器页面持有同一配对时可触发。

## 根因

Go 和 Cloudflare 中继每个配对只保留一个 host / guest 连接。新同角色连接进入后，旧连接收到
WebSocket `1000`、reason=`replaced`。旧 Web 将它当普通断网自动重连，重新踢掉新页面；
两个页面不断争抢。单页面截图或一次短暂「已连接」不能证明多页面稳定。

2026-11-02 用独立临时测试配对在真实中继验证：两个客户端先后连接，旧客户端收到 replaced。
未使用用户已有配对，验收后删除了临时配对。

## 修法

- `PairClient` 仅对明确 `1000/replaced` 停止该客户端，进入 `replaced` 状态；普通网络断开继续重连。
- 关闭直连、心跳和同步重试，忽略迟到业务帧；保留配对凭据、会话投影和缓存，不能走 revoke。
- App 显示「已在其他页面连接」及手动「在此页面连接」。只有用户显式点击才创建新客户端，
  并重新订阅原会话；focus / visibility / online 等自动事件不能接管。
- 线上验收不要再打开另一个持有相同配对的页面去与用户抢连；使用临时配对或被动检查。

## 回归防线

`packages/phone/src/client.test.ts` 覆盖：替换后 60 秒无重连、前台 / 网络事件不接管、缓存保留、
旧直连回执被丢弃、第二客户端持续在线，以及普通 1006 断网仍自动重连。
真实中继测试观察旧客户端只出现 `connecting → online → replaced`，新客户端保持 online，
没有反复创建连接。

更新后让旧页面刷新或关闭多余页面，不清除浏览器存储，不让用户重新配对来掩盖根因。
