# 代码搜索反复耗尽预算，已命中的代码也全部丢失

## 症状

`code_search` 返回 `Code search exhausted its command budget before a verified final answer`，
或 `Invalid Devin JSON response`。看似是查询太宽，实际连几个文件的示例库也经常只能
返回 `partial`。2026-10-30 排查的近期 14 次调用中，8 次报错、6 次部分返回。

## 根因

这是**内部检索协议和收尾控制层**的问题，不是主模型传入的外层 query/path 一定有错：

- 内部模型实际发出 6–8 条命令，旧 schema 每轮只接受 4 条；丢弃后半批还永久标记
  整次结果不完整。模型实际使用正则，旧本地实现却按字面搜索，导致无效轮次累积。
- 说明文字或云端坏 JSON 可直接跳出搜索；6+2 轮结束没交出 `ANSWER` 时，也没有保留
  已读代码的降级出口。预算错误不等于没有匹配。
- 最终重读共用扫描物理读取预算；扫描耗尽就无法验证答案。片段总量超过中间预算
  也会在最终文本裁剪之前整体报错。
- mock 响应全部遵守本地自定义 schema，离线测试全绿不能证明私有模型线上遵守协议。

## 修法

命令方言与真实响应对齐，但不放宽总执行量、路径边界或外发预算。正则交给有界原生
匹配器处理，不能直接执行模型控制的 JavaScript RegExp 或 shell。

观察记录必须来自本地生成的可信元数据，只保留实际回传过的完整代码行；不能解析
不可信源码里的路径来“恢复结果”。协议/收尾失败可以重新围栏验证这些范围并返回
明确的 `partial`；取消、认证、网络和安全拒绝不能被降级掩盖。

当前权威预算与具体行为见 [内置代码搜索](../main/code-search.md)。

## 回归防线

- 先 RED 复现预算丢证据、八命令批次、坏协议、最终片段超限，再实现 GREEN。
- 覆盖源码伪造路径、未回传正文、目录列表、超量/拒绝命令不能生成证据；降级仍重读
  最新内容，删除/缩短可跳过，越界和 symlink 竞争必须硬失败。
- 原生正则用临时文件真跑；子进程取消、超时、输出上限必须等待 `close` 后收束。
- 至少两个厂商的真实主模型调用同一工具；不能用离线 fixture 代替线上协议验证。
  本轮验收记录见 [2026-10-30 可靠性修复](../../project-history/2026-10-30-code-search-reliability.md)。
