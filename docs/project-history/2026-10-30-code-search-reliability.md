# 代码搜索协议兼容与证据降级验收

## 范围与边界

用户反馈 `code_search` 几乎从未成功，最近一次角色首页查询报命令预算耗尽。
修复仅在 worker 内的 `codeSearch` 文件层、原生匹配器和搜索循环；不改账号、IPC、
Renderer、工具默认授权或模型路由，不新增依赖，不发版或替换已安装应用。

初查抽样的 27 次历史调用有 19 次错误、8 次带文件的部分结果；仅看 10 月 29 日起，
14 次中有 8 次错误、6 次部分结果。此统计包含不同查询和版本，不是固定数据集成功率。
真实服务在人工四源码文件示例中也发出 8/6 条批次和正则，复现旧协议不匹配。

## 修复与自动验证

- 接受每轮 8 条结构化命令，但整个搜索仍最多 24 条、6+2 响应、90 秒。
- 默认支持原生 Rust ripgrep 正则，支持显式字面匹配；stdin 只接收围栏后的代码，
  子进程无 shell/用户配置，并限制时间、输出和取消收尾。
- 协议纠正在原响应预算内继续；没交最终答案时，只能用本地记录、实际回传的完整
  代码行降级为 `partial`，最终重新读取。认证/网络/取消/安全错误不走降级。
- 最终重读预算与扫描隔离，大答案按完整行裁剪并保持结构化范围一致。
- 安全测试额外暴露旧版最终答案吞掉路径穿越的行为，已改为硬失败。

采用 RED→GREEN；相关 10 个测试文件共 **146 项通过**。复核补充了超长模式、坏
命令路径、原生进程缺 stdio 和最终重读预算不足的回归。随后全量检查：

- `pnpm typecheck`：通过。
- `pnpm lint`：通过；保留既有 `GitChangesView.tsx` 的非阻断 fragment 提示。
- `pnpm test`：Vitest **875 文件 / 9965 用例通过，2 文件 / 7 用例跳过**；
  之前的 Node 脚本测试也通过。
- `pnpm build`：通过，保留既有动态导入 / chunk 大小警告。
- `pnpm knowledge:check`：新增链接通过；整体检查因 `AGENTS.md` 已有的两条本机
  `.proma` 记忆链接失效而非零退出，保留既有知识条目结构警告，不扩大本次修复范围。

## 隔离 Electron 双厂商真机

独立临时 userData、CDP 9333；核对监听 PID 和 `ENSO_USER_DATA_DIR`，未写真实配置。
仅使用人工创建的角色首页示例库，不发送用户业务代码或 EnsoCode 源码。

真实主模型分别为 OpenAI `auto/gpt-6.1-sol` 和 Anthropic `omc/claude-opus-5-5`，
各自新建父会话，自主调用一次 `code_search`，`path:"src"`，内部使用真实 Devin 服务。
安全复核补修后重启隔离实例，在最终代码上又各跑一次新会话，结果一致。

两轮都观测到实际 running、seq 推进及 turn-completed；Main 权威历史里都有真实
工具调用与非错误结果，worker JSONL 的结构化详情均为：

```text
status: success
warnings: []
src/routing/home.ts
src/auth/roles.ts
src/auth/permissions.ts
src/pages/login.ts
```

两主模型均正确解释角色到首页映射、登录入口和权限函数。父会话文本投影没有展示
`details.status`，因此没有用模型口述推断状态，而是核对 worker 权威结构化结果。
验收后停止隔离实例，删除测试会话、临时账号副本和示例目录。
