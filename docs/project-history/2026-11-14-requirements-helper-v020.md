# 需求助手 v0.2.0：按真实需求表简化

## 用户要求与行为差距

用户要求插件展示名不超过5字，并明确反馈上一版太复杂、看不懂、感觉未完成；提供当前项目金山需求表授权测试。确定名称为“需求助手”，主流程改为：粘贴链接 → 读取待办 → 开始处理 → 确认并交给Agent → 查看结果 → 预览确认回填。

真实表只有需求/优先级/状态/负责人/预计天数/提出人/备注，没有唯一编号和测试列，当前需求状态留空。旧版强制编号、测试列、JSON列映射、已知值校准和空白测试开关，不适合该用户流程。这些工程配置移出主界面，由表头识别、范围元数据核对、冲突检测替代；没有删除远程写入的确认边界。

## 关键实现

- 显示名/视图/按钮统一为4字“需求助手”，版本0.2.0，保留插件ID以兼容安装记录。
- 自动识别表头、按负责人筛选，空状态当待处理。无编号按需求正文与负责人生成稳定身份；重复内容拒绝领取，不擅自改表加编号。
- 无测试列时只写状态和备注，人工备注保留，追加简短处理/测试/复测说明，不增加列。
- 只留下链接和负责人两项配置。报告从JSON换成普通表单，工具卡“查看结果”带入实际结果。
- 用户点“确认并交给Agent”才先领取再注入当前对话；agent.inject为新增授权，升级需重新同意。发送记录先标unknown，失败不自动重放。
- 发现真实WPS的画布编辑器input.value恒空，不能用普通input夹具冒充；新受限copy_selection捕获当次复制内容及零基范围，新insert_text输入已聚焦透明代理。范围名只显示左上格，复制元数据必须完整匹配。
- 修复已领取条目仍在待办、已交付按钮仍可点、旧报告实际测试内容未带入等状态问题。

## 尚未证明与交付边界

- 未自动安装、启用、重启用户dev或发布桌面版/市场。当前宿主需包含新增op；只有旧安装版装ZIP不够，dev须重启Main并更新插件。
- 真实服务端验证的是整表读取和单个空白格写入/清空，不是已在用户需求上完成“领取→模型修改→报告→交付”。未因此声称PWA图片问题已修。
- 两个不同厂商真实模型的工具验收仍未完成；不能把模拟/夹具作为替代。
